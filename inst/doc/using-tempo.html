Using TEMPO

TEMPO gives R access to the Romanian National Institute of Statistics’ TEMPO Online database: roughly 1500 statistical matrices covering population, labour, agriculture, trade, prices and more.

The database is an external service, so the chunks that need it are shown but not evaluated when this vignette is built. The chunks that need nothing but the package itself do run, so the output you see for them is real.

A two-minute tour

library(TEMPO)

# 1. Find a table.
tables <- tempo_search("unemployed", language = "en")
tables[, c("code", "name")]

# 2. Look at its structure, and its size, before downloading anything.
meta <- tempo_meta("SOM101E", language = "en")
meta

# 3. Pull the slice you need straight into a data frame.
unemployment <- tempo_get(
  "SOM101E",
  filters = list(
    Sex        = "Total",
    Counties   = "Cluj",
    Localities = "TOTAL",
    Periods    = grep("2024", meta$values$Periods$label, value = TRUE)
  ),
  language = "en"
)
head(unemployment)

The package has three entry points, in increasing order of commitment: tempo_toc() and tempo_search() tell you what exists, tempo_meta() describes one table, and tempo_get() or tempo_bulk() fetch data.

Finding a table

Start from the table of contents. The default language is Romanian; set language = "en" for English table names.

tables <- tempo_toc(language = "en")
nrow(tables)
head(tables)

The result has a name and a code, plus a comment when the service supplies one. Searching it is common enough to have its own function, which accepts several patterns and searches every character column:

tempo_search(c("population", "migration"), language = "en")

# Reuse a table of contents you already hold rather than fetching it again.
tempo_search("population", toc = tables)

The service stores table names without diacritics, so search for the unaccented spelling: "sanatate", not the accented form.

Where a table sits in the classification

Two routes give you the statistical domain, sub-domain and survey.

tempo_hierarchy() reads the service’s own navigation tree. The branch structure, currently 8 domains, 70 sub-domains and 262 surveys, arrives in a single request:

branches <- tempo_hierarchy(language = "en", matrices = FALSE)
table(branches$level)
subset(branches, level == 1, select = c(code, name))

The service does not include matrices in that listing, so placing every matrix in the tree costs one further request per survey. Those are issued concurrently and cached, and the default matrices = TRUE does it for you:

tree <- tempo_hierarchy(language = "en")

# Where does one matrix sit?
tree[tree$code == "POP105A", c("level", "path")]

# Every matrix under one domain.
population <- tree[tree$is_matrix & grepl("POPULATIE", tree$path), ]
head(population[, c("code", "name")])

tempo_toc(full_description = TRUE) attaches the same three levels to every row of the table of contents. It has to ask about each matrix in turn, so even with concurrent requests and caching the first call takes a while:

described <- tempo_toc(full_description = TRUE, language = "en")
head(described[, c("code", "Statistical_domain", "Last_update")])

# What has been revised most recently?
head(described[order(described$Last_update, decreasing = TRUE), ])

Last_update is a Date, so it sorts and filters directly. The service embeds HTML links in its top-level domain labels; those are stripped from every text column, and the URLs are kept in Press_releases.

Looking before downloading

A TEMPO matrix can be very large: county-by-locality tables crossed with decades of years run to millions of observations. tempo_meta() tells you what you are about to ask for, in a single request.

meta <- tempo_meta("SOM101E", language = "en")
meta
#> <tempo_meta> SOM101E
#>   A. SOCIAL STATISTICS > LABOUR FORCE > REGISTERED UNEMPLOYED
#>   language:    en
#>   last update: 2026-10-12
#>   full table:  88,663,248 cells, over 2,000 requests
#>                too large to fetch whole; select values with tempo_get()
#>   dimensions:  5
#>     1. Sex (3 values): Total, Male, Female
#>     2. Counties (43 values): TOTAL, Alba, Arad, ...
#>     3. Localities (3182 values): TOTAL, 1017 ALBA IULIA MUNICIPALITY, ...
#>     4. Periods (216 values): Year 2010, January 2010, February 2010, ...
#>     5. MU: Persons (1 value): Number of persons

Two things in that output are worth dwelling on. The table has 88 million cells, so it cannot be downloaded whole and tempo_bulk() would refuse it. And the unit of measure is a dimension of its own, MU: Persons, because that is how the service models it; [tempo_tidy()] later moves it out of the data into a unit column.

The components are there for programmatic use:

meta$dimensions      # one row per dimension, with how many values each has
meta$cells           # size of a full download
meta$requests        # how many HTTP requests that would take
meta$values$Years    # the selectable values, with the service's identifiers

Getting data into R

tempo_get() sends your selection to the service and returns a data frame. Dimensions you do not mention come back whole, which for a table like the one above would be far too much, so name the ones that matter:

unemployment <- tempo_get(
  "SOM101E",
  filters = list(
    Sex        = "Total",
    Counties   = "Cluj",
    Localities = "TOTAL",
    Periods    = grep("2024", meta$values$Periods$label, value = TRUE)
  ),
  language = "en"
)

Taking the Periods labels from meta rather than writing them out is worth the habit: it keeps the call working whatever format the service uses for those labels.

Filter values are matched against the dimension’s labels: first exactly, ignoring case and surrounding space; then as a whole token, so 2024 finds "January 2024"; and finally against the service’s own numeric identifiers. A value that matches nothing is an error that lists what is available, rather than a quietly smaller result:

tempo_get("SOM101E", filters = list(Counties = "Atlantis"), language = "en")
#> Error: No value of dimension "Counties" matches "Atlantis". Available
#> values (first 10 of 43): TOTAL; Alba; Arad; Arges; Bacau; ...

Dimension names can be abbreviated, or given by position:

tempo_get("SOM101E", filters = list(Count = "Cluj", Period = "January 2024"),
          language = "en")

What tidying does

The CSV that TEMPO Online returns needs work before it can be analysed, and tempo_get() applies tempo_tidy() by default. This chunk runs, so you can see exactly what changes. It is the service’s own layout, including a footer line and an observation marked ":":

csv <- paste(
  "Judete,Ani,UM: Numar persoane,Valoare",
  "Cluj,Anul 2019,Numar persoane,1234",
  "Cluj,Anul 2020,Numar persoane,:",
  "Bihor,Anul 2019,Numar persoane,987",
  ",,,(c) INS 1998-2026",
  sep = "\n"
)
cat(csv)
#> Judete,Ani,UM: Numar persoane,Valoare
#> Cluj,Anul 2019,Numar persoane,1234
#> Cluj,Anul 2020,Numar persoane,:
#> Bihor,Anul 2019,Numar persoane,987
#> ,,,(c) INS 1998-2026
tidy <- tempo_tidy(csv, code = "DEMO101A")
tidy
#>   Judete  Ani           unit value
#> 1   Cluj 2019 Numar persoane  1234
#> 2   Cluj 2020 Numar persoane    NA
#> 3  Bihor 2019 Numar persoane   987
str(tidy)
#> 'data.frame':    3 obs. of  4 variables:
#>  $ Judete: chr  "Cluj" "Cluj" "Bihor"
#>  $ Ani   : int  2019 2020 2019
#>  $ unit  : chr  "Numar persoane" "Numar persoane" "Numar persoane"
#>  $ value : num  1234 NA 987
#>  - attr(*, "tempo_code")= chr "DEMO101A"
#>  - attr(*, "tempo_unit")= chr "Numar persoane"

Four things happened:

  • the unit of measure moved out of the UM: column header into a unit column;
  • Valoare became a numeric value, with ":" mapped to NA;
  • "Anul 2019" became the integer 2019;
  • the trailing copyright line was dropped, while the row whose observation is missing was kept, because its dimension columns are filled.

Sub-annual tables also gain a Date column, which is what makes them usable in a time-series workflow without per-project label parsing. This is the layout with a separate Luni dimension:

monthly <- paste(
  "Luni,Ani,UM: Numar,Valoare",
  "luna ianuarie,Anul 2024,Numar,10",
  "luna februarie,Anul 2024,Numar,12",
  "luna decembrie,Anul 2024,Numar,14",
  sep = "\n"
)
tempo_tidy(monthly)
#>             Luni  Ani  unit value     period
#> 1  luna ianuarie 2024 Numar    10 2024-01-01
#> 2 luna februarie 2024 Numar    12 2024-02-01
#> 3 luna decembrie 2024 Numar    14 2024-12-01

Quarters and semesters are parsed the same way, in Romanian and English.

Many matrices, including SOM101E above, instead use a single Periods dimension whose labels mix frequencies. Those labels are left exactly as received, because the label is the only thing separating an annual total from a monthly figure of the same year, and year and period columns are added alongside:

mixed <- paste(
  "Counties,Periods,UM: Persons,Value",
  "Cluj,Year 2010,Number of persons,100",
  "Cluj,January 2010,Number of persons,8",
  "Cluj,February 2010,Number of persons,9",
  sep = "\n"
)
tempo_tidy(mixed)
#>   Counties       Periods              unit value year     period
#> 1     Cluj     Year 2010 Number of persons   100 2010       <NA>
#> 2     Cluj  January 2010 Number of persons     8 2010 2010-01-01
#> 3     Cluj February 2010 Number of persons     9 2010 2010-02-01

period is NA on the annual row, so subset(x, !is.na(period)) gives the monthly series and subset(x, is.na(period)) the annual totals.

If a value cannot be read as a number, it is reported once with a warning and the original text is kept in a value_raw column, so an unexpected flag becomes visible instead of silently turning into NA:

odd <- paste(
  "Judete,Ani,UM: Numar,Valoare",
  "Cluj,Anul 2019,Numar,1234",
  "Bihor,Anul 2019,Numar,confidential",
  sep = "\n"
)
suppressWarnings(tempo_tidy(odd))
#>   Judete  Ani  unit value    value_raw
#> 1   Cluj 2019 Numar  1234         1234
#> 2  Bihor 2019 Numar    NA confidential

Pass tidy = FALSE to tempo_get() to skip all of this and receive the service’s layout verbatim, every column a character vector.

Downloading whole tables to disk

tempo_bulk() writes complete matrices as CSV files, which suits a pipeline that reads the same tables repeatedly or needs them outside R.

data_directory <- file.path(tempdir(), "tempo-data")

files <- tempo_bulk(
  codes = c("ACC101B", "ACC101C"),
  language = "en",
  directory = data_directory
)

files
attr(files, "downloaded")
attr(files, "reason")

The return value names every requested matrix, whether or not it was fetched in this call, so the path is always available:

accidents <- tempo_tidy(files[["ACC101B"]], code = "ACC101B")

Reusing local files correctly

Next to the CSV files, tempo_bulk() keeps a .tempo-manifest.json recording, for each file, the language, the service’s own update string, the retrieval time, the number of requests spent and an MD5 checksum. A file is reused only when the language, the published revision and the checksum all agree.

tempo_bulk("ACC101B", language = "en", directory = data_directory)
#> Skipping `ACC101B`: the local CSV is up to date.
#> All requested CSV files are up to date.

# Asking for the other language re-downloads rather than reusing the file.
tempo_bulk("ACC101B", language = "ro", directory = data_directory)

# Force a download regardless.
tempo_bulk("ACC101B", language = "en", directory = data_directory,
           overwrite = TRUE)

The manifest is also the provenance record for a reproducible pipeline: it says which revision of each matrix your results were computed from, and when it was retrieved.

Large tables

The service will not answer an arbitrarily large query, so a download is split into chunks whose product of selected values stays within getOption("TEMPO.max_cells"), and the parts are concatenated. Each part’s CSV header is compared with the first part’s, so misaligned columns are an error rather than a corrupt file.

You rarely need to touch this, but the controls exist:

options(
  TEMPO.max_cells = 1e5,       # larger single queries
  TEMPO.max_connections = 2,   # gentler on the service
  TEMPO.throttle = 0.2         # at least 0.2s between requests
)

See ?"TEMPO-options" for the full list. TEMPO Online is a small public service with no published rate limit; the defaults are deliberately modest.

Caching

The table of contents and the per-matrix metadata change rarely and are expensive to fetch, so they are cached. By default the cache lives in the session’s temporary directory and disappears with the session:

tempo_cache_dir()
#> [1] "C:\\Users\\maria\\AppData\\Local\\Temp\\RtmpIBY74F/TEMPO-cache"

To keep it between sessions, point it somewhere persistent:

tempo_cache_dir(tools::R_user_dir("TEMPO", "cache"))

# Or, in a project .Rprofile:
options(TEMPO.cache_dir = tools::R_user_dir("TEMPO", "cache"))

tempo_cache_clear()

Observations are never cached; only metadata is.

When the service misbehaves

TEMPO Online goes down, changes its response format, and occasionally returns a 500 that succeeds on the next attempt. Transport failures and the statuses worth retrying are retried with exponential backoff before an error surfaces at all.

What does surface carries a class, so a script can tell a mistake of its own from a problem at the other end:

tryCatch(
  tempo_toc(language = "fr"),
  tempo_input_error = function(condition) "my call was wrong",
  tempo_offline_error = function(condition) "the service is unreachable",
  tempo_error = function(condition) "something else"
)
#> [1] "my call was wrong"
# Read the HTTP status, and retry only what is worth retrying.
tryCatch(
  tempo_get("ACC101B"),
  tempo_http_error = function(condition) {
    message("HTTP ", condition$status_code, " from ", condition$url)
    NULL
  },
  tempo_offline_error = function(condition) {
    Sys.sleep(60)
    tempo_get("ACC101B")
  }
)

?"TEMPO-conditions" lists every class and the fields it carries. A plain tryCatch(expr, error = ...) still catches all of them.

Moving from version 0.1.0

The 0.1.0 API still works. Two behaviours changed on purpose:

  • tempo_bulk() now returns the paths of all requested matrices, named by code, rather than only the newly written ones. Code that looped over the result still works; code that relied on skipped files being absent should consult attr(files, "downloaded").
  • tempo_toc(full_description = TRUE) returns Last_update as a Date instead of a character string, and its Statistical_domain no longer contains raw HTML.

Everything else is new: tempo_get(), tempo_meta(), tempo_tidy(), tempo_search(), tempo_hierarchy(), tempo_cache_dir().
